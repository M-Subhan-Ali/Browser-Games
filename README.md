# Browser Games Portal

A **guest-only browser game portal** built to run at **$0** on Cloudflare's free tier —
no login, no database bill, no server to pay for. Visitors open the site, pick a game,
and play instantly. The only data ever kept about a player is an anonymous ID and an
optional nickname, both stored on their own device.

---

## Core ideas

1. **Everything is static.** The portal is a Next.js app exported to plain HTML/JS
   (`output: "export"`). No running server for page views, so page traffic is free and
   unlimited on Cloudflare Pages.
2. **Games are sandboxed.** Each game is a self-contained HTML file that runs inside an
   `<iframe>`. A game can't touch the portal's code or the network directly — it only
   talks to the portal through a tiny SDK over `postMessage`.
3. **The catalog is a file, not a database.** `content/catalog.json` is the single
   source of truth. Adding a game = adding a JSON entry + an HTML file. No admin panel,
   no backend write.

## Architecture

```
                 The player's browser
   ┌─────────────┐        ┌────────────────────┐
   │  Cloudflare │  HTML  │   PORTAL PAGE       │   postMessage bridge
   │  Pages      │───────►│  (Next.js static)   │◄───────────────────┐
   │  (portal)   │        │   GameFrame.tsx     │   validates & acts  │
   └─────────────┘        │     ├─ <iframe> ────┼──► ┌──────────────┐ │
                          │     │               │    │ GAME (iframe)│ │
   ┌─────────────┐  game  │     └───────────────┼◄───┤ index.html + │─┘
   │  Cloudflare │  files │                     │    │ portal-sdk   │
   │  Pages      │───────►│  localStorage +     │    └──────────────┘
   │  (games)    │        │  IndexedDB (local)  │
   └─────────────┘        └─────────────────────┘
```

**A play session** (`/play/<slug>/`):

1. Cloudflare Pages serves pre-built static HTML for the route (one page per game,
   generated by `generateStaticParams()`).
2. `GameFrame.tsx` renders an `<iframe>` pointing at the game and attaches the
   `postMessage` listener.
3. The game loads `portal-sdk.js`, calls `Portal.ready()` to handshake, then
   `Portal.load()` / `Portal.getPlayer()` to restore progress and identity.
4. On game over the game calls `Portal.save({...})` (→ IndexedDB) and
   `Portal.submitScore(score)`.

Every incoming message is checked: the portal only acts on messages whose `origin`
matches the expected games origin **and** whose `source` is the exact iframe it created.

**Two origins.** Untrusted game code is isolated on a *different* origin from the portal
so a bug or malicious script in a game can't read the portal's storage or cookies. In
production that's a second Cloudflare Pages project (`NEXT_PUBLIC_GAMES_ORIGIN`).
Locally, games are copied into the portal's `public/g/` folder and served same-origin —
zero extra infrastructure.

## The game contract

A game plugs into the portal through exactly two things: a **catalog entry** and the
**SDK**.

**Catalog entry** (`content/catalog.json`) — one object per game, driving the home page,
category pages, search, the `/play/<slug>/` route, and credits:

```jsonc
{
  "slug": "chess",
  "title": "Chess",
  "version": "v1",
  "categories": ["board", "strategy"],
  "description": "Full-rules chess vs. AI",
  "controls": ["mouse", "touch"],
  "featured": true,
  "new": true,
  "leaderboard": false,
  "needsNickname": false,
  "license": { "type": "MIT", "author": "…", "source": "…", "permissionFile": "licenses/chess.txt" }
}
```

**SDK** (`games/portal-sdk.js`) — the only channel a game has to the outside. Every call
is a `postMessage` to the portal that returns a Promise:

| SDK call | Purpose | Status |
|---|---|---|
| `Portal.ready()` | Handshake; hides the loading spinner | ✅ working |
| `Portal.getPlayer()` | Get `{ id, nickname }`; prompts for a nickname if needed | ✅ working |
| `Portal.save(data)` / `Portal.load()` | Persist / restore up to 1 MB of progress (IndexedDB) | ✅ working |
| `Portal.gameplayStart()` / `gameplayStop()` | Mark active play | ✅ working |
| `Portal.submitScore(n)` / `getLeaderboard()` | Leaderboard | ⏳ stubbed (needs the Worker) |

Games "fail safe": even though `submitScore`/`getLeaderboard` are stubbed today, games
still run and save their local best score via `Portal.save`.

## Data & privacy

All player data is **guest-only and device-local** (`apps/web/lib/player.ts`):

| Data | Storage | Key |
|---|---|---|
| Anonymous ID | `localStorage` | `portal:playerId` |
| Nickname (optional, 3–16 chars) | `localStorage` | `portal:nickname` |
| Recently played (max 12) | `localStorage` | `portal:recent` |
| Per-game saves (≤ 1 MB each) | IndexedDB | `save:<slug>` |

No email, password, IP, or location is ever collected. "Clear my data" on the privacy
page wipes the local ID/nickname.

## Getting started

**Prerequisites:** Node.js and **pnpm 10.30.3** (`corepack enable` provides the right pnpm).

```bash
pnpm install            # from the repo root; installs the whole workspace

cd apps/web
pnpm dev                # predev copies games into public/g, then starts Next dev
# open http://localhost:3000
```

Other scripts (from the repo root, via Turborepo):

```bash
pnpm build              # build the static site → apps/web/out/
pnpm lint               # eslint across the workspace
pnpm typecheck          # next typegen + tsc --noEmit
```

## Adding a new game

No backend work — four steps:

1. **Game file:** `games/<slug>/v1/index.html` — self-contained, includes
   `<script src="../../portal-sdk.js">`, follows the `ready → load → play → save` lifecycle.
2. **License:** `licenses/<slug>.txt`.
3. **Register:** add one object to `content/catalog.json`.
4. **Mirror:** automatic — `copy-games.mjs` runs on `pnpm dev` / `pnpm build`.

Then `pnpm dev` and open `/play/<slug>/`.

## Deploy (the $0 Cloudflare plan)

1. **Portal** → Cloudflare Pages project #1. Build command `pnpm build`, output
   directory `apps/web/out`.
2. **Games** → Cloudflare Pages project #2 deploying the `games/` folder. Set
   `NEXT_PUBLIC_GAMES_ORIGIN` on the portal to that URL so games load cross-origin.
3. Replace the placeholder hostnames (`yourportal*.pages.dev`) in both `_headers` files.
4. **Leaderboards (later):** build the Hono Worker + D1, add Turnstile, and swap the
   stubs in `GameFrame.tsx` for real `fetch` calls.

**Stack:** Next.js 16.4.2 · React 19.3 · Tailwind CSS v4 · Fuse.js · idb-keyval ·
Turborepo · pnpm workspaces.
